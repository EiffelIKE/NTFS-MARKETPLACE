## 1. Dependencies and version decisions

| Package | Version | Kind | Why |
|---|---|---|---|
| `msw` | `^2.15.0` | runtime | Worker and handlers ship in the demo build (API-34). `package.json#msw.workerDirectory: ["public"]` keeps `public/mockServiceWorker.js` in sync on install. |
| `big.js` | `^7.0.1` | runtime | Decimal arithmetic for ETH (API-07). Small, no dependencies, has a `strict` mode that rejects `number` input. |
| `@types/big.js` | `^7.0.0` | dev | |

Versions are the newest that met the 7-day `minimumReleaseAge` on 2026-10-27, checked against peer ranges.

- **MSW 2.15, not 3.0.** `msw@3.0.3` exists, but `@mswjs/socket.io-binding@0.2.0` (latest, which brief §6 points to and spec 03 needs) declares `peerDependencies.msw: ^2.10.2`. Revisit when the binding supports 3.x.
- **No `@mswjs/data`.** The mock database is a small typed store (§7): we need exact control over persistence, transactions, versioning and change events, and a custom store gives that with no extra API to learn.
- **Axios `adapter: 'fetch'` (amends spec 00 §6).** With the default XHR adapter, Axios hands its timeout to the browser's native `xhr.timeout`, which Playwright's clock cannot control. The fetch adapter enforces the timeout with `setTimeout` (`helpers/composeSignals.js` in axios 1.20), which `page.clock` and `vi.useFakeTimers()` both control (API-43). The timeout error keeps code `ETIMEDOUT`, which `toApiError` already maps to `timeout`. The FND-15 lint rule bans `fetch` in our code; Axios calling it internally is fine.

## 3. Environment and bootstrap (API-34)

`lib/env.ts` gains `VITE_ENABLE_MOCKS: z.enum(['true', 'false']).default('true').transform((v) => v === 'true')`. Strings are spelled out so a typo like `1` fails fast instead of silently turning mocks off. `.env.example` documents it. A real backend does not exist, so the default is on, both locally and on Vercel.

**Static guard.** For the "no mock code in the bundle" rule, `vite.config.ts` parses the env (spec 00 already does) and writes the result back as `define: { 'import.meta.env.VITE_ENABLE_MOCKS': JSON.stringify(String(parsed.VITE_ENABLE_MOCKS)) }`. The default then applies at build time too, and the guard in `main.tsx` folds to a literal:

```ts
async function prepare() {
  if (import.meta.env.VITE_ENABLE_MOCKS === 'true') {
    const { startMocks } = await import('@/mocks/browser')
    await startMocks()
  }
}
void prepare().then(renderApp, renderBootError)
```

With the flag off, Rollup drops the dynamic import and no `mocks/` chunk is emitted.

**`startMocks()` order:**

1. Read `scenario`, `reset` and `mockPanel` from `location.search`. Remove `scenario` and `reset` with `history.replaceState`, so the router (spec 05 search schemas) never sees them.
2. Load config and database (§7, §10):
   - A valid `scenario` that differs from the active one: switch, which reseeds and clears overrides.
   - `reset=1`: reseed the active scenario.
   - An unknown id: `console.warn` and keep the current scenario.
3. `await worker.start(...)` with these options:
   - `serviceWorker.url: '/mockServiceWorker.js'`;
   - `quiet: import.meta.env.PROD`;
   - `onUnhandledRequest`: bypass everything outside the API base. The API base cannot be unhandled because of the catch-all handler.
4. Set `window.__mock` (§11). Arm the settlement timer (§8.4). Mount the panel when requested (§11).

**Failure.** If the worker cannot start (no Service Worker support, or an insecure origin), `renderBootError` shows "Não foi possível iniciar a simulação da API" with the reason and a reload button. The app never falls through to a nonexistent backend.

### Resource schemas (summary; the Zod files are the source of truth)

**Auth** (desktop login/sign-up modal and mobile pages in Figma)
- `SignupBody`: `{ username: 3–20 [a-z0-9_], email, password }`. Password policy: 8–72 characters, at least one letter and one digit. "Confirmar senha" is checked on the client only.
- `LoginBody`: `{ email, password: min 1 }`.
- `User`: `{ id, username, displayName, email, avatarUrl: string | null }`. `displayName` starts equal to `username`.
- `SessionPayload`: `{ token, expiresAt, user }`.
- `SessionInfo`: `{ expiresAt, user }`.

**Catalog**
- `NftListQuery`: `{ q?: ≤ 80, categories?: CategoryId[], networks?: NetworkId[], minPrice?: Eth, maxPrice?: Eth, segment: 'all' | 'new' | 'trending' = 'all', sort: 'recent' | 'price-asc' | 'price-desc' | 'popular' = 'recent', favorites?: true, page: ≥ 1 = 1, pageSize: 1–48 = 9 }`.
  - On the wire, arrays are comma-joined (`categories=musica,arte-3d`) and `favorites=true`.
  - The handler rejects `minPrice > maxPrice` with 422.
- `CategoryId`: `arte-digital | fotografia | musica | arte-3d | colecionaveis | generativa | jogos | assinaturas | utilidade` (labels pt-BR, from Figma).
- `NftSummary`: `{ id, name, collection: { id, name }, category, network, image: Image, price: Eth, previousPrice?: Eth, rarity: 'common' | 'rare' | 'epic' | 'legendary', available: boolean, listedAt, version }`.
  - `price` belongs to the NFT; every edition sells at that price (Figma: Ivory Baron 1/10 × 2 = 3.58 at the 1.79 list price).
  - `available` is true while at least one edition has stock.
- `NftListResponse`: `Page<NftSummary> & { applied: NftListQuery (normalized), facets: { categories: { id, label, count }[], networks: { id, label, count }[], price: { min: Eth, max: Eth } | null } }`.
- `Edition`: `{ id: 'unique' | 'limited-10' | 'limited-50' | 'open', label: '1/1' | '1/10' | '1/50' | 'ABERTA', supply: int | null, available: int | null, maxPerOrder: int }`.
  - `null` supply and availability mean an open edition.
  - Availability counts what remains after pending orders' reservations.
- `NftDetail`: `NftSummary & { description, longDescription: string[] (paragraphs), tokenId, creator: { name, username }, attributes: string[], specs: { network: string, royalty: string, contract: { address, standard: 'ERC-721' | 'SPL' } }, royaltyBps: int, images: Image[] (1–4), editions: Edition[] (1–4, fixed order), rating: number (0–5, one decimal), reviewCount: int, reviews: { id, author, rating: 1–5, comment, createdAt }[] (≤ 3) }`.
  - `specs` feeds the "Rede / Contrato / Direitos autorais" list in the order the labels mean (Figma swaps the last two values; spec 06 records the deviation).
- `Highlights`: `{ hero: { id, nftId, eyebrow, title, shortTitle, description, shortDescription, image }[], featured: { nftId, title, subtitle, image } | null }`.
  - `shortTitle` and `shortDescription` are the mobile copy (Figma uses different text on the mobile hero).

**Cart and quote**
- `AddCartItemBody`: `{ nftId, editionId, quantity: Quantity }`.
- `UpdateCartItemBody`: `{ quantity?: Quantity, acknowledgePrice?: true }`, at least one of the two.
- `CartItem`: `{ id, nftId, editionId, name, tokenId, editionLabel, image, quantity, unitPrice: Eth, addedUnitPrice: Eth, lineTotal: Eth, available: int | null, maxQuantity: int, status: 'ok' | 'price_changed' | 'limited' | 'unavailable' }`.
  - `lineTotal` is shown per row in the Figma cart; the summary totals still come only from the quote.
- `Cart`: `{ id: string | null, items: CartItem[], coupon: Coupon | null, itemCount: int, version: int, updatedAt }`.
  - `id` is `null` for a guest who has no cart yet.
- `Coupon`: `{ code, kind: 'percent' | 'fixed', value: string, description }`.
- `CartMergeResult`: `{ cart: Cart, adjustments: { nftId, editionId, requested, applied, reason: 'capped' | 'unavailable' }[] }`.
- `Quote`: `{ id, network, lines: { itemId, nftId, editionId, quantity, unitPrice, lineTotal }[], subtotal, discount, networkFee, total, coupon: Coupon | null, issues: QuoteIssue[], purchasable: boolean, issuedAt }`.
- `QuoteIssue`: `{ code: 'UNAVAILABLE' | 'INSUFFICIENT_AVAILABILITY' | 'PRICE_CHANGED' | 'COUPON_EXPIRED' | 'COUPON_NOT_APPLICABLE' | 'CART_EMPTY', itemId?, blocking: boolean }`.

**Orders** (fields from the Figma checkout "Perfil do colecionador" form)
- `CollectorDetails`: `{ displayName*, username*, profileName*, email*, ensName* (label without `.eth`), referralCode*: 4–16 [A-Z0-9-], walletAddress*, alternateWallet?: address or ENS }`. Starred fields are required in Figma. Spec 09 prefills them from the profile and the chosen wallet.
- `CreateOrderBody`: `{ quoteId, walletId, provider: WalletProvider, network, collector: CollectorDetails, note?: ≤ 500 }`.
  - `network` must be one the wallet's address family supports; the checkout "Rede" select offers only those.
- `Order`: `{ id, status: 'pending' | 'confirmed' | 'declined', lines: { nftId, editionId, name, tokenId, editionLabel, image, quantity, unitPrice, lineTotal }[], subtotal, discount, networkFee, total, coupon, network, wallet: { id, role, nickname, address, ensName, provider }, collector, note, transaction: { hash, explorerUrl, explorerName } | null, declineReason: { code: 'PAYMENT_DECLINED', message } | null, createdAt, updatedAt, settledAt: IsoDateTime | null, version }`.
  - The Figma receipt shows the transaction id, date, total, wallet provider ("MetaMask"), lines with quantity and subtotal, network fee, total, the network name and "Ver no Etherscan" (`explorerName`).
- `OrderSummary`: `Pick<Order, 'id' | 'status' | 'total' | 'network' | 'createdAt' | 'version'> & { itemCount }`.

**Profile** (Figma "Perfil do colecionador")
- `Profile`: `{ id, displayName, username, email, ensName: string | null, walletNickname: string | null, avatarUrl: string | null, createdAt }`.
- `UpdateProfileBody`: `{ displayName*: 2–40, username*: 3–20 [a-z0-9_], email*, ensName*: 3–40 [a-z0-9-] (stored without `.eth`), walletNickname*: 1–32 }`. A full replace, because every Figma field is required; a new account has `ensName` and `walletNickname` empty until the first save.
- `ChangePasswordBody`: `{ currentPassword, newPassword }`, where the new password follows the policy and differs from the current one. "Confirmar nova senha" is checked on the client only.

**Wallets** (Figma "Carteiras": one primary and one secondary slot)
- `WalletProvider`: `'metamask' | 'walletconnect' | 'coinbase'` (labels "MetaMask", "WalletConnect", "Coinbase Wallet").
- `WalletFields`: `{ displayName*, nickname*: 1–32, network*: NetworkId, profileName*, address*, alternateWallet?, provider*: WalletProvider, referralCode*, email*, ensName* }`. Same validation as `CollectorDetails` for shared fields.
- `CreateWalletBody`: `WalletFields & { role: 'primary' | 'secondary' }`. "Igual à carteira principal" is a client shortcut that copies the primary's fields into the form.
- `Wallet`: `WalletFields & { id, role, family: 'evm' | 'solana', createdAt, updatedAt }`. `family` is derived from the address.
- `WalletConnection`: `{ id, walletId, provider, network, status: 'connected' | 'disconnected', connectedAt, disconnectedAt: IsoDateTime | null }`.

**Networks**
- `PaymentNetwork`: `{ id, name, fee: Eth, walletFamily: 'evm' | 'solana', explorerName, explorerTxUrl: string }`. `explorerTxUrl` is a template ending in `/tx/`.

## 5. Money (`lib/money.ts`, API-06 – API-09)

```ts
const D = Big()            // private constructor, global Big untouched
D.strict = true            // new D(1.5) throws: no number may enter
D.DP = 18; D.RM = Big.roundDown

export const eth = {
  parse(v: Eth): Big,                  // throws on an invalid string (contracts validated it already)
  add(...v: Eth[]): Eth, sub(a: Eth, b: Eth): Eth, times(a: Eth, qty: number): Eth,   // qty integer, checked
  percent(a: Eth, bps: number): Eth,  // a × bps / 10000, rounded down at 18 decimals
  min(a: Eth, b: Eth): Eth, cmp(a: Eth, b: Eth): -1 | 0 | 1, isZero(a: Eth): boolean,
}
export function formatEth(v: Eth): string   // "1.19 ETH"
export function formatEthAmount(v: Eth): string   // "1.19" (for ranges: "0.02 - 12.30 ETH")
```

- Results are normalized strings through `toFixed()`, which has no exponent, and trailing zeros are kept only up to two decimals.
- **Formatting rule (API-08):**
  - integer part as is, no grouping;
  - fractional part padded to 2 digits and never cut (`0.00042` stays `0.00042`);
  - suffix `" ETH"`, joined with a non-breaking space so the amount never wraps away from its unit.
- Fixture prices have ≤ 4 decimals, fees ≤ 4 and percentage coupons are whole percents, so every derived amount has ≤ 6 decimals. Nothing reaches the formatter needing a rounding decision.
- **Rounding rule (API-09):** only `percent()` can produce more digits; it rounds toward zero at 18 decimals. A fixed coupon is `min(value, subtotal)`.

## 6. Endpoint functions and errors (API-03 – API-05, API-12)

### `ApiError` (extends spec 00 §6)

```ts
export type ApiErrorKind = 'network' | 'timeout' | 'http' | 'cancelled' | 'contract' | 'unknown'
export class ApiError extends Error {
  readonly kind: ApiErrorKind
  readonly status: number | undefined
  readonly code: ApiErrorCode | undefined     // http: parsed envelope code, or 'UNKNOWN'
  readonly fields: Record<string, string[]> | undefined
  readonly details: unknown
  readonly operation: OperationId | undefined
}
export function isApiError<C extends ApiErrorCode>(e: unknown, code?: C): e is ApiError & { code: C; details: DetailsOf<C> }
```

- `toApiError` parses `response.data` with `ErrorEnvelope.safeParse`. A missing or invalid body gives `code: 'UNKNOWN'` and keeps `status`.
- `isRetryable` is unchanged, and `contract` is not retryable.
- `message` is the envelope message when present, otherwise a generic pt-BR message per kind.

### `request()` (`api/request.ts`)

```ts
export async function request<S extends z.ZodType>(op: {
  id: OperationId; method: Method; url: string; response: S
  params?: Record<string, string | undefined>; data?: unknown; headers?: Record<string, string>; signal?: AbortSignal
}): Promise<z.output<S>>
```

- The helper calls `http.request(...)`, which already maps errors to `ApiError` via the interceptor, and tags the error with `op.id`.

- On success it runs `response.safeParse(data)`. On failure it throws `ApiError({ kind: 'contract', operation })`, and `console.error` prints the issues in development.

### Store (`db/store.ts`)

- **Storage adapter:** `{ get, set, remove }`. In the browser it is `localStorage`; in Node it is a `Map`.
- **Keys:**
  - `kurio.mock.db` holds the state;
  - `kurio.mock.config` holds `{ scenarioId, overrides }` (§10);
  - `kurio.mock.panel` is a session flag for the launcher.
- **`load()`:** parse the stored state. When it is missing, does not parse, or has the wrong `schemaVersion`, run `seed(scenario.seed)` and persist; `console.info` says why.
- **`read(fn)`:** runs `fn` against the in-memory state.
- **`write(fn)`:**
  1. `structuredClone` the state and run `fn(draft)`.
  2. If `fn` throws, discard the draft. This makes every handler atomic: no partial cart or order on a 4xx.
  3. On success, swap the state, persist it synchronously, then publish the buffered domain changes.
- **Quota error:** `console.warn`, and keep the in-memory state.
- **Multi-tab:** a `storage` event on `kurio.mock.db` reloads the in-memory state, last write wins. Domain changes publish only in the tab that made the mutation. Spec 03 documents this limitation.
- **Time** is always `Date.now()`, which Playwright's clock and Vitest fake timers both control.

## 8. Handlers (`mocks/handlers/`)

### 8.1 Pipeline (`pipeline.ts`)

`route(op, handler)` registers `http[method](base + path)` for each operation in `contracts/operations.ts`. Every request then goes through these steps:

1. **Log** `{ seq, at, op, method, url, status: 'pending' }`. The log is a ring buffer of 500 entries.
2. **Network, before** (§10): apply the failure rules for `phase: 'before'`, which can return a network error, an HTTP error or a hang. Then apply latency (fixed, range or out-of-order). Waiting races `request.signal`, so an aborted request logs `aborted` and stops (API-05 proof).
3. **Settlement tick:** run `settleDue(now)` (§8.4).
4. **Session:** resolve the bearer.
   - Unknown or malformed token: `UNAUTHENTICATED`.
   - Expired token: `SESSION_EXPIRED`, and the session is deleted.
   - Private operations require a session; optional-auth operations ignore an invalid token only when none was sent.
5. **Body:** parse JSON, with a 422 when it does not parse, then the request schema. A `ZodError` becomes 422 `VALIDATION_FAILED` with `fields` keyed by dotted path. Query strings go through the same schema with coercion.
6. **Handler:** run inside `store.write` or `store.read`. Domain rules throw `HttpError(status, code, { fields?, details? })`, and the pipeline turns it into the envelope. Any other throw becomes 500 `INTERNAL` plus `console.error`.
7. **Network, after:** a `timeout` rule with `phase: 'after'` hangs here, after the write committed. This is the "order created, response lost" case.
8. **Log** the final status.

`fallback.ts` answers any other path under the base with 404 `NOT_FOUND`.

### 8.2 Catalog (`domain/catalog-query.ts`)

- **Search:** fold the query and the fields with `normalize('NFD')`, strip diacritics, lowercase, then substring match. The fields are name, collection, creator and attributes.
- **Filters:**
  - `segment=new`: `listedAt ≥ CATALOG_REFERENCE_DATE − 30 days`, where `CATALOG_REFERENCE_DATE = 2026-10-01T00:00:00Z` is a fixture constant, so results do not depend on the clock.
  - `segment=trending`: `trendingScore ≥ 70`.
  - Price filters compare `price` with `eth.cmp`.
  - `favorites` restricts to the session user's favorites.
- **Sort:**
  - `recent`: `listedAt` descending;
  - `price-asc` and `price-desc`: by `price`;
  - `popular`: `trendingScore` descending;
  - ties are broken by `id` ascending.
- **Facets:**
  - each category and network count runs the query with all filters except its own dimension (disjunctive faceting);
  - `price` bounds run with all filters except price;
  - all categories and networks are always listed, including zero counts.
- **Pagination:** a page beyond the last returns `items: []` with real totals. `applied` echoes the normalized query, so tests and stale-response checks can compare it with the parameters sent.
- **Related:** up to 5 other NFTs from the same collection, by `listedAt` descending, filled from the same category if the collection has fewer.

### 8.3 Cart, coupons, quote (`domain/cart.ts`, `domain/quote.ts`)

- **Cart key:**
  - with a session: `user:<id>`;
  - without one: `guest:<X-Guest-Cart-Id>`;
  - a guest `GET` without a known id returns `{ id: null, items: [] }`;
  - a guest's first `POST /cart/items` creates `g_<seq>` and returns it as `cart.id`, which spec 07 stores.
- **Line limit:** `maxQuantity = min(available ?? Infinity, maxPerOrder)`.
  - Adding to an existing line sums the quantities.
  - Over the limit: 409 `INSUFFICIENT_AVAILABILITY` with `available`.
  - `available === 0`: 409 `EDITION_UNAVAILABLE`.
- **Line status**, highest priority first:
  - `unavailable` when `available === 0`;
  - `limited` when `quantity > maxQuantity` (stock dropped after adding);
  - `price_changed` when `unitPrice ≠ addedUnitPrice`;
  - `ok`.

  `acknowledgePrice: true` copies `unitPrice` into `addedUnitPrice`. `cart.version` increases on every cart write.
- **Coupon apply:**
  - codes are case-insensitive and stored upper-case;
  - unknown: `COUPON_INVALID`;
  - `expiresAt < now`: `COUPON_EXPIRED`;
  - current subtotal below `minSubtotal`: `COUPON_NOT_APPLICABLE`.

  Removing a coupon is idempotent.
- **Merge:** for each guest line, add it to the user's cart under the line limit and record the adjustments (`capped`, or `unavailable` when the line was dropped). Then delete the guest cart. An unknown `guestCartId` returns the user's cart with `adjustments: []`.
- **Quote** (pure: `quote(cart, nfts, coupons, network, now)`):
  - `unavailable` lines get a blocking `UNAVAILABLE` issue and are excluded from the totals;
  - `limited` lines get a blocking `INSUFFICIENT_AVAILABILITY` issue and are counted at their current quantity;
  - `price_changed` lines get a non-blocking `PRICE_CHANGED` issue;
  - a coupon that is now expired or not applicable gives a non-blocking issue and a discount of `0`;
  - an empty cart gives a blocking `CART_EMPTY` issue and a fee of `0`;
  - `discount = coupon.kind === 'percent' ? eth.percent(subtotal, bps) : eth.min(value, subtotal)`;
  - `networkFee` is the network's fixed fee;
  - `total = subtotal − discount + networkFee`;
  - `purchasable = no blocking issue`;
  - `id = 'q_' + sha256(canonicalJson({ network, lines: [itemId, nftId, editionId, quantity, unitPrice], coupon, discount, networkFee, total, issueCodes })).slice(0, 24)`.

### 8.4 Orders (`domain/orders.ts`)

**`orders.create`**, in order:
1. A missing or malformed `Idempotency-Key` gives 422 with `fields['Idempotency-Key']`.
2. Look up `idempotency[userId:key]`:
   - found with the same body fingerprint (`sha256(canonicalJson(body))`): 200 with the current order, whatever its status;
   - found with a different fingerprint: 409 `IDEMPOTENCY_CONFLICT`.
3. The user has a `pending` order: 409 `ORDER_PENDING`.
4. Validate the body:
   - the wallet must belong to the user (403 otherwise);
   - the wallet must support `network` (422);
   - there must be a `connected` connection for (wallet, provider, network), otherwise 409 `WALLET_NOT_CONNECTED`;
   - `collector` and `note` are validated with their schemas (422 with `fields` keyed `collector.<field>`).
5. Run the scenario checkout trigger, once (§10).
6. Recompute the quote:
   - a blocking availability issue gives 409 `INSUFFICIENT_AVAILABILITY`;
   - `quote.id ≠ body.quoteId` gives 409 `QUOTE_CHANGED` with `{ quote }`;
   - any other blocking issue gives 409 `QUOTE_CHANGED` as well.
7. Create `ord_<seq padded to 6>` as `pending`:
   - snapshot the lines, amounts, coupon, network, wallet and contact (API-25);
   - reserve stock by decrementing `available` on limited editions, then bump `nft.version` and publish `nft.updated`;
   - set `settleAt = now + config.payment.settleDelayMs`;
   - store the idempotency record, publish `order.updated` and re-arm the settlement timer.
8. Respond 201.

**Settlement** (`settleDue(now)`):
- **When it runs:** at the start of every handled request, and from one `setTimeout` armed for the earliest `settleAt`, re-armed on boot and on each create. A reload therefore resumes progress from the persisted timestamps (API-24).
- **Which orders:** only pending orders with `settleAt ≤ now`, and only when `config.payment.outcome` is not `manual`.
- **Confirmed:**
  - `transaction.hash = '0x' + sha256(id + createdAt)` (64 hex);
  - `explorerUrl` = the network's `explorerTxUrl` + hash, under the reserved `explorer.kurio.example` domain, which is simulated and never resolves;
  - for each order line, decrement that quantity in the user's current cart line with the same NFT and edition, removing the line at ≤ 0, and bump `cart.version`.
- **Declined:**
  - `declineReason = { code: 'PAYMENT_DECLINED', message: 'A carteira recusou o pagamento.' }`;
  - release the reservations, capped at supply, and publish `nft.updated` for each.
- **Both:** set `settledAt`, increase `version` and publish `order.updated`. Terminal orders are never touched again.

**Other operations:**
- `orders.get` returns the stored snapshot, so catalog edits never reach it.
- `orders.list` filters the session user's orders, newest first.

### 8.5 Account (`domain/auth.ts`)

- **Password hash:** `pbkdf2-sha256$100000$<salt b64>$<hash b64>` via WebCrypto (`crypto.subtle`, available in browsers on secure origins and in Node 24), with a 16-byte random salt. Verification compares in constant time. 100 000 iterations keeps logins under ~100 ms in tests; this is a simulation, so `ARCHITECTURE.md` (spec 14) notes that a production setting would be higher.
- **Signup:**
  - normalize the email (trim, lowercase) and check uniqueness;
  - reject a taken `username` with 409 `USERNAME_TAKEN` on `username`;
  - set `displayName = username`, `ensName` and `walletNickname` to `null`;
  - create an empty profile and return a session.
- **Session:**
  - the token is `crypto.randomUUID()` without dashes, which is opaque;
  - `expiresAt = now + config.sessionTtlMs`, a fixed TTL with no sliding;
  - logout deletes the session;
  - a password change deletes every other session of the user.
- **Avatar:**
  - `415` unless the MIME type is `image/png`, `image/jpeg` or `image/webp` and the magic bytes match;
  - `413` when the file is over 2 MB;
  - the browser adapter resizes to 256 × 256 WebP with `createImageBitmap` and `OffscreenCanvas`, and stores it as a data URL of ~10–40 KB;
  - the Node adapter stores the input as is.

### 8.6 Wallets (`domain/wallets.ts`)

- **Slots:** each user has at most one `primary` and one `secondary` wallet (Figma "Carteira principal" / "Carteira secundária"). Creating a role that already exists is 409 `WALLET_ROLE_TAKEN`. Roles never swap; the user edits a slot instead.
- **Address vs. network:**
  - EVM: `/^0x[0-9a-fA-F]{40}$/`, valid for `ethereum` and `polygon`;
  - Solana: base58 `/^[1-9A-HJ-NP-Za-km-z]{32,44}$/`, valid for `solana`.

  An address that does not match the chosen `network` is 422 on `address` ("Endereço inválido para a rede selecionada."). `alternateWallet`, when present, must be a valid address of any family or an ENS name (`*.eth`).
- **Duplicates:** the same address in both slots of one user is 409 `WALLET_DUPLICATE` (compared case-insensitively for EVM, exactly for Solana).
- **Connection:**
  - `connect` checks that `network` is valid for the wallet's family (422), then waits `config.walletConnect.delayMs` (a page timer);
  - with outcome `reject`, it returns 409 `WALLET_REJECTED`;
  - otherwise it creates `connected` and closes any previous connection of the same wallet.
- **Disconnection:** `disconnect` sets `disconnected`. A simulated disconnection from `__mock.disconnectWallet()` does the same. Spec 03 may surface it as an event.

## 10. Scenarios and network conditions (API-39 – API-43)

### Config (`config.ts`)

```ts
interface MockConfig {
  latency: { kind: 'none' } | { kind: 'fixed'; ms: number } | { kind: 'range'; minMs: number; maxMs: number }
  outOfOrder: { ops: OperationId[]; slowMs: number; fastMs: number } | null   // odd calls slow, even fast, per op
  rules: FailureRule[]
  payment: { outcome: 'confirm' | 'decline' | 'manual'; settleDelayMs: number }
  walletConnect: { outcome: 'approve' | 'reject'; delayMs: number }
  realtime: { available: boolean; deliveryDelayMs: number }   // spec 03; `offline` sets available: false
  sessionTtlMs: number
  checkoutTrigger: 'raise-price' | 'sell-out' | null   // once per seed, on the first orders.create
  prngSeed: number                                     // drives 'range' latency
}
interface FailureRule {
  id: string; op: OperationId | '*'
  effect: { kind: 'http'; status: number; code: ApiErrorCode } | { kind: 'network-error' } | { kind: 'timeout'; phase: 'before' | 'after' }
  times: number | 'always'                             // decremented per matching call
}
```

**Effective config.** It is `scenario.config` deep-merged with the persisted `overrides`, set through `__mock.configure()` and the panel. Rule counters and the out-of-order counter live in memory and restart on reload, so a scenario is reproducible from a fresh page load.

**Effects:**
- `network-error` → `HttpResponse.error()`; the client sees `kind: 'network'`.
- `timeout` → never resolves; the client's Axios timeout fires.
- `range` latency → successive draws from the seeded PRNG, in request order.

**Checkout triggers:**
- `raise-price` raises the first cart line's NFT price by 10 %, rounded to 4 decimals.
- `sell-out` sets its availability to 0.

Both bump the version and publish. Revalidation then fails with `QUOTE_CHANGED` or `INSUFFICIENT_AVAILABILITY`. `triggers.checkoutFired` keeps them one-shot until reset.

- Every mutating method goes through `store.write`, so it persists and publishes like a handler does. `updateNft` therefore produces `nft.updated`, which is how spec 03 and 09 tests change prices "on the server".

## 14. Deviations and notes for `ARCHITECTURE.md` (spec 14)

- MSW pinned to 2.x because of the Socket.IO binding's peer range (§1).
- Axios uses the fetch adapter so timeouts follow fake clocks (§1).
- **Quotes have no stored id or expiry.** The id is a content fingerprint, so any change in price, availability, coupon or fee invalidates it (§8.3).
- **Another user's private resource returns 403, not 404.** This makes the brief's "insufficient permissions" case observable (§4).
- **All amounts are in ETH, including on Solana.** The payment network only changes the fee and the wallet family (decision 3).
- **ETH is shown with a dot decimal separator**, including the filter label that Figma writes with commas (decision 4).
- **PBKDF2 uses 100 000 iterations**, a simulation setting (§8.5).
- **Mock time is the browser clock.** Settlement resumes after reload from persisted timestamps (§8.4).
- **Multi-tab:** last write wins, and domain changes publish only in the tab that wrote them (§7).
- **Service worker limits:** MSW needs a secure context (HTTPS or `localhost`). The first visit pays the worker registration cost, which spec 13 analyzes.

**Contracts and errors**
- `AuthMode` has a fifth value, `'lenient'`, for `auth.logout`: it accepts a missing or expired token and still answers 204.
- `INSUFFICIENT_AVAILABILITY.details.lines[].available` is the line limit `min(available, maxPerOrder)`, which is what the user can actually take.
- A `details` object that does not match its code's schema turns the whole error into code `UNKNOWN` (the client does not narrow on a broken contract). A bad envelope also gives `UNKNOWN`.
- Client `ApiError` messages are pt-BR per kind (`network`, `timeout`, `cancelled`, `contract`, `unknown`) and one generic pt-BR text for HTTP errors without a valid envelope.
- `z.config(z.locales.ptBR())` is set in the mock pipeline so server-side validation messages are pt-BR; client forms keep their own messages.
- Prices are normalized strings (`'12.3'` becomes `'12.30'`) in `toRecord`, `updateNft` and the cart status compare (`eth.cmp`), so string equality never decides a price change.

**Mock behavior**
- Multi-word search: every word must match somewhere in name, collection, creator or attributes.
- The `sell-out` checkout trigger zeroes the first cart line's own edition (the first version only zeroed a limited edition, which left open editions untouched).
- A guest cart id the server does not know is treated as no cart. On merge the user's cart keeps its own coupon and otherwise inherits the guest cart's.
- A `timeout` failure rule is evaluated before latency, so it never waits first.
- Avatar checks run in the order MIME (415), magic bytes (415), size (413).
- The `empty-catalog` seed has no NFTs, favorites, cart lines or highlights, but still contains Ana's seeded order: orders are self-contained snapshots, so they need no catalog.
- `createHandlers(runtime)` and `createMockServer()` returning `{ server, runtime, control }` are the public factories; there is no module-level singleton.

**Panel**
- Files are `mount.tsx` and `mock-panel.tsx` (they contain JSX), not `.ts`.
- Payment has two buttons for pending orders, "Confirmar pedidos pendentes" and "Recusar pedidos pendentes", instead of one "Liquidar".
- The README mention in the panel footer is plain text (no link: the panel has no README route).
- The launcher flag is a `sessionStorage` key, `kurio.mock.panel`.

**Test and tooling**
- `useMockApi` was renamed `serveMockApi` (the `use` prefix tripped `react-hooks/rules-of-hooks`). Test helpers `*-kit.ts` and `*.test.ts` share one ESLint override (mocks allowed, `fetch` allowed, to probe raw HTTP).
- The Abort case uses `queryClient.query()`: `fetchQuery` is deprecated in TanStack Query 5.104.
- TanStack's `cancelQueries()` rejects with its own `CancelledError`, not an `ApiError`. The test asserts the rejection plus the `aborted` log entry, and checks `kind: 'cancelled'` with a direct `AbortController`.
- Vitest fake timers use `shouldAdvanceTime: true`: MSW's interceptors schedule their own 0 ms timers and would hang otherwise.
- **Browser limit:** a page-side abort never reaches the service worker, so in the browser the request log shows the final status (`200`) instead of `aborted`. Cancellation in the UI must be proved from the page side. Node tests do see `aborted`.
- Reset (`?reset=1`, `useScenario`) clears sessions, so E2E tests log in again afterwards.
